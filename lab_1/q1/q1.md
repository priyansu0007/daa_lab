# Algorithmic Growth-Rate Comparison Using a Log-Log Plot

## 1. Objective

This experiment compares the growth rates of the following functions:

\[
\frac{1}{n},\quad \log_2 n,\quad 12\sqrt n,\quad 50n^{0.5},\quad n^{0.51},
\]

\[
2^{32}n,\quad n\log_2 n,\quad n^2-324,\quad 100n^2+6n,
\]

\[
2n^3,\quad n^{\log_2 n},\quad 3^n
\]

The goal is to visualize how quickly these functions grow as \(n\) increases and compare their asymptotic time complexities. Since some functions become extremely large, the values are plotted after applying \(\log_{10}\).

---

## 2. Approach

The solution uses three components:

1. **C program (`.c`)**  
   Generates the transformed data and stores it in `data_loglog.txt`.

2. **Gnuplot script (`.plt`)**  
   Reads the generated data and creates the graph.

3. **PNG graph (`complexity.png`)**  
   Visualizes all twelve functions on logarithmic axes.

The C program does not directly calculate every function value. Instead, it calculates:

\[
x=\log_{10}(n)
\]

and

\[
y=\log_{10}(f(n))
\]

This prevents overflow and makes functions with very different growth rates visible on the same graph.

---

## 3. Data Generation Strategy

### 3.1 Exponentially increasing values of \(n\)

The loop starts at \(n=20\) and doubles \(n\) after every iteration:

```c
for (double n = 20; n <= 10000000; n *= 2)
```

Using exponential spacing is useful because the horizontal axis is logarithmic. If \(n\) is multiplied by \(2\), then:

\[
\log_{10}(2n)=\log_{10}(n)+\log_{10}(2)
\]

Therefore, consecutive points are evenly spaced on the log-scaled x-axis.

This also reduces the number of data points while still covering a large range:

\[
20 \le n \le 10^7
\]

The number of iterations is approximately:

\[
\log_2\left(\frac{10^7}{20}\right)
\]

which is about 19 iterations.

---

## 4. Logarithmic Transformations

The program uses logarithm rules to avoid calculating very large values directly:

\[
\log_{10}(ab)=\log_{10}(a)+\log_{10}(b)
\]

\[
\log_{10}(a^b)=b\log_{10}(a)
\]

The transformed values are calculated as follows.

| Function | Transformation used in the program |
|---|---|
| \(\frac1n\) | \(-\log_{10}(n)\) |
| \(\log_2 n\) | \(\log_{10}(\log_2 n)\) |
| \(12\sqrt n\) | \(\log_{10}(12)+0.5\log_{10}(n)\) |
| \(50n^{0.5}\) | \(\log_{10}(50)+0.5\log_{10}(n)\) |
| \(n^{0.51}\) | \(0.51\log_{10}(n)\) |
| \(2^{32}n\) | \(32\log_{10}(2)+\log_{10}(n)\) |
| \(n\log_2 n\) | \(\log_{10}(n)+\log_{10}(\log_2 n)\) |
| \(n^2-324\) | \(\log_{10}(n^2-324)\) |
| \(100n^2+6n\) | \(\log_{10}(100n^2+6n)\) |
| \(2n^3\) | \(\log_{10}(2)+3\log_{10}(n)\) |
| \(n^{\log_2 n}\) | \(\log_2(n)\log_{10}(n)\) |
| \(3^n\) | \(n\log_{10}(3)\) |

### Avoiding overflow

The transformation is especially important for:

\[
3^n
\]

For \(n=10^7\), directly calculating \(3^n\) is impossible using normal floating-point values. However:

\[
\log_{10}(3^n)=n\log_{10}(3)
\]

can be calculated safely.

Similarly:

\[
\log_{10}\left(n^{\log_2 n}\right)
=
\log_2(n)\log_{10}(n)
\]

avoids directly computing the very large value \(n^{\log_2 n}\).

---

## 5. Time-Complexity Comparison

The constants and lower-order terms affect actual values but do not affect asymptotic complexity.

| Function | Asymptotic complexity | Growth category |
|---|---:|---|
| \(\frac1n\) | \(O(1/n)\) | Decreasing |
| \(\log_2 n\) | \(O(\log n)\) | Logarithmic |
| \(12\sqrt n\) | \(O(\sqrt n)\) | Sublinear |
| \(50n^{0.5}\) | \(O(\sqrt n)\) | Sublinear |
| \(n^{0.51}\) | \(O(n^{0.51})\) | Sublinear |
| \(2^{32}n\) | \(O(n)\) | Linear |
| \(n\log_2 n\) | \(O(n\log n)\) | Linearithmic |
| \(n^2-324\) | \(O(n^2)\) | Quadratic |
| \(100n^2+6n\) | \(O(n^2)\) | Quadratic |
| \(2n^3\) | \(O(n^3)\) | Cubic |
| \(n^{\log_2 n}\) | Quasi-polynomial | Superpolynomial |
| \(3^n\) | \(O(3^n)\) | Exponential |

---

## 6. Ordering from Slowest to Fastest Growth

For sufficiently large \(n\), the functions are ordered approximately as:

\[
\frac1n
<
\log n
<
\sqrt n
<
n^{0.51}
<
n
<
n\log n
<
n^2
<
n^3
<
n^{\log_2 n}
<
3^n
\]

The two square-root functions have the same asymptotic growth:

\[
12\sqrt n=\Theta(\sqrt n)
\]

\[
50n^{0.5}=\Theta(\sqrt n)
\]

Their graph lines are parallel because they differ only by a constant factor:

\[
\log_{10}(50\sqrt n)
=
\log_{10}(50)+0.5\log_{10}(n)
\]

The constant changes the vertical position but not the growth rate.

Similarly:

\[
n^2-324=\Theta(n^2)
\]

and

\[
100n^2+6n=\Theta(n^2)
\]

Both are quadratic even though their plotted values are separated.

---

## 7. Interpretation of the Graph

The graph uses:

- x-axis: \(\log_{10}(n)\)
- y-axis: \(\log_{10}(f(n))\)

### Important observations

**1. \(1/n\) decreases**

The graph of \(\frac1n\) slopes downward because its value approaches zero as \(n\) increases:

\[
\log_{10}\left(\frac1n\right)=-\log_{10}(n)
\]

---

**2. Polynomial functions appear as straight lines**

For:

\[
f(n)=cn^k
\]

we have:

\[
\log_{10}(f(n))
=
\log_{10}(c)+k\log_{10}(n)
\]

Thus, polynomial functions become straight lines on the graph.

Their slope is equal to the exponent \(k\):

- \(\sqrt n=n^{0.5}\): slope \(0.5\)
- \(n^{0.51}\): slope \(0.51\)
- \(n\): slope \(1\)
- \(n^2\): slope \(2\)
- \(n^3\): slope \(3\)

This explains why the cubic function rises more quickly than the quadratic functions.

---

**3. Constants shift curves vertically**

The functions:

\[
12\sqrt n
\]

and

\[
50\sqrt n
\]

have identical asymptotic complexity. The factor \(50\) causes its line to appear above the factor \(12\) line, but both have the same slope.

Likewise, \(2^{32}n\) is still linear:

\[
2^{32}n=\Theta(n)
\]

The very large constant shifts the line upward but does not change its asymptotic complexity.

---

**4. \(n\log n\) grows faster than linear**

The function:

\[
n\log n
\]

grows faster than \(n\), but slower than \(n^2\). Its graph is not a perfect straight line because of the additional logarithmic factor.

---

**5. \(n^{\log_2 n}\) is superpolynomial**

Using:

\[
\log_2 n=\frac{\log n}{\log 2}
\]

we can rewrite:

\[
n^{\log_2 n}
=
2^{(\log_2 n)^2}
\]

It grows faster than every fixed-degree polynomial, such as \(n^2\), \(n^3\), or \(n^{100}\), but slower than a standard exponential function such as \(3^n\).

---

**6. \(3^n\) grows the fastest**

The exponential function rapidly exceeds the other functions. Its transformed value is:

\[
\log_{10}(3^n)=n\log_{10}(3)
\]

Even after applying the logarithm, it grows extremely quickly. The graph's y-axis is restricted to:

```gnuplot
set yrange [-2:60]
```

so that the other curves remain visible. Without this limit, the \(3^n\) curve would dominate the plot and compress the slower-growing functions near the x-axis.

---

## 8. Complexity of the C Program

The C program generates one row for every value:

\[
20,\ 40,\ 80,\ 160,\ldots
\]

Since \(n\) doubles each iteration, the number of loop iterations is:

\[
O(\log N)
\]

where \(N\) is the maximum value of \(n\).

Each iteration performs a constant number of mathematical operations and file writes. Therefore:

### Time complexity

\[
\boxed{O(\log N)}
\]

### Auxiliary space complexity

\[
\boxed{O(1)}
\]

The output file itself contains \(O(\log N)\) rows, but the program uses only constant auxiliary memory while generating it.

---

## 9. Conclusion

The experiment demonstrates the difference between **actual function values** and **asymptotic growth rates**.

Constants such as \(12\), \(50\), \(2^{32}\), and \(100\) can significantly change the vertical position of a curve, but they do not change Big-O complexity. Likewise, lower-order terms and constant offsets do not affect the dominant growth rate for large \(n\).

The final asymptotic ordering is:

\[
\boxed{
\frac1n
<
\log n
<
\sqrt n
<
n^{0.51}
<
n
<
n\log n
<
n^2
<
n^3
<
n^{\log_2 n}
<
3^n
}
\]

The log-log approach makes it possible to compare all these functions over a large range while avoiding numerical overflow and clearly revealing their relative growth behavior.
