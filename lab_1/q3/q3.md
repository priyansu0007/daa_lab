# Q3. Performance Analysis of Optimized and Unoptimized Bubble Sort

## Problem Statement

Bubble Sort is a simple comparison-based sorting algorithm.

In this experiment, two versions of Bubble Sort are implemented and their performance is compared:

1. **Optimized Bubble Sort**
   - Stops early if the array becomes sorted before completing all passes.
   - Uses a `swapped` flag to detect whether any exchange occurred during a pass.

2. **Unoptimized Bubble Sort**
   - Always completes all possible passes regardless of whether the array is already sorted.

The program generates **nearly sorted random arrays**, applies both algorithms on the same data, counts the number of comparisons, and plots the comparison results using GNUplot.

---

# Objective

The objective of this experiment is to:

- Compare the efficiency of optimized and unoptimized Bubble Sort.
- Analyze the effect of early termination on nearly sorted data.
- Observe how the number of comparisons grows with increasing input size.
- Visualize the performance difference using a graph.

---

# C Program

```c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

// Optimized Bubble Sort
long long bubbleSortOptimized(int arr[], int n) {

    long long comparisons = 0;

    for (int i = 0; i < n - 1; i++) {

        int swapped = 0;

        for (int j = 0; j < n - i - 1; j++) {

            comparisons++;

            if (arr[j] > arr[j + 1]) {

                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;

                swapped = 1;
            }
        }

        // Stop if array is already sorted
        if (swapped == 0) {
            break;
        }
    }

    return comparisons;
}


// Unoptimized Bubble Sort
long long bubbleSortUnoptimized(int arr[], int n) {

    long long comparisons = 0;

    for (int i = 0; i < n - 1; i++) {

        for (int j = 0; j < n - i - 1; j++) {

            comparisons++;

            if (arr[j] > arr[j + 1]) {

                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }

    return comparisons;
}


// Generates nearly sorted random array
void generateNearlySortedRandom(int arr[], int n) {

    for (int i = 0; i < n; i++) {
        arr[i] = i;
    }

    // Perform random swaps
    for (int i = 0; i < 5; i++) {

        int idx1 = rand() % n;
        int idx2 = rand() % n;

        int temp = arr[idx1];
        arr[idx1] = arr[idx2];
        arr[idx2] = temp;
    }
}


// Copies array
void copyArray(int source[], int dest[], int n) {

    for (int i = 0; i < n; i++) {
        dest[i] = source[i];
    }
}


int main() {

    FILE *fp = fopen("bubble_data.dat", "w");

    if (fp == NULL) {
        printf("Error opening file!\n");
        return 1;
    }

    srand(time(NULL));

    int max_n = 2000;
    int step = 100;

    fprintf(fp, "# N Unoptimized_Comps Optimized_Comps\n");


    for (int n = step; n <= max_n; n += step) {

        int *original = malloc(n * sizeof(int));
        int *test1 = malloc(n * sizeof(int));
        int *test2 = malloc(n * sizeof(int));


        generateNearlySortedRandom(original, n);


        copyArray(original, test1, n);
        copyArray(original, test2, n);


        long long comp_unopt = bubbleSortUnoptimized(test1, n);
        long long comp_opt = bubbleSortOptimized(test2, n);


        fprintf(fp, "%d %lld %lld\n",
                n,
                comp_unopt,
                comp_opt);


        free(original);
        free(test1);
        free(test2);
    }


    fclose(fp);

    printf("Data generated and saved to 'bubble_data.dat'.\n");

    return 0;
}
```

# Theory

## Bubble Sort

Bubble Sort repeatedly compares adjacent elements and swaps them if they are in the wrong order.

Example:

```
5 3 8 1
```

First pass:

```
3 5 1 8
```

Second pass:

```
3 1 5 8
```

The largest elements gradually move toward the end of the array.

---

# Optimized Bubble Sort

The optimized version uses a flag:

```c
int swapped = 0;
```

During each pass:

- If any swap occurs:
  - `swapped` becomes `1`.
- If no swap occurs:
  - The array is already sorted.
  - The algorithm terminates immediately.

This avoids unnecessary comparisons.

---

# Unoptimized Bubble Sort

The unoptimized version always performs all passes:

```
n-1 passes
```

even if the array becomes sorted earlier.

This results in unnecessary comparisons, especially for nearly sorted data.

---

# Approach

The program follows these steps:

1. Generate a nearly sorted array.
2. Create two copies of the same array.
3. Apply:
   - Optimized Bubble Sort on one copy.
   - Unoptimized Bubble Sort on the other copy.
4. Count the comparisons performed by each algorithm.
5. Store results in:

```
bubble_data.dat
```

6. Plot the comparison count using GNUplot.

---

# Generation of Nearly Sorted Data

The function:

```c
generateNearlySortedRandom()
```

first creates a sorted array:

```
0 1 2 3 4 5 6 7 ...
```

Then it performs five random swaps.

Example:

Before:

```
0 1 2 3 4 5 6 7
```

After swaps:

```
0 1 5 3 4 2 6 7
```

The array is mostly sorted but contains small disorder.

This type of input highlights the advantage of optimized Bubble Sort.

# Dry Run

Consider:

```
Array:
1 2 4 3 5
```

## Optimized Bubble Sort

### Pass 1

Compare:

```
1 and 2 → No swap
2 and 4 → No swap
4 and 3 → Swap
3 and 5 → No swap
```

Array becomes:

```
1 2 3 4 5
```

Since a swap happened, continue.

### Pass 2

Compare:

```
1 and 2
2 and 3
3 and 4
```

No swaps occur.

The algorithm stops.

---

## Unoptimized Bubble Sort

Even though the array is sorted after the first pass, it continues performing all remaining passes.

This increases the number of comparisons.

---

# Algorithm

## Optimized Bubble Sort

1. Start from the first element.
2. Compare adjacent elements.
3. Swap if they are in incorrect order.
4. Track whether any swap occurred.
5. If no swaps occur, stop immediately.
6. Repeat until sorted.

---

## Unoptimized Bubble Sort

1. Perform `n-1` passes.
2. Compare adjacent elements.
3. Swap when required.
4. Continue until all passes are complete.

# Complexity Analysis

## Optimized Bubble Sort

### Best Case

Already sorted array:

```
O(n)
```

Only one pass is required.

---

### Average Case

```
O(n²)
```

---

### Worst Case

Reverse sorted array:

```
O(n²)
```

---

## Unoptimized Bubble Sort

The algorithm always completes all passes.

Best, average, and worst cases:

```
O(n²)
```

---

# Space Complexity

Both algorithms sort in-place.

Only temporary variables are used.

Therefore:

```
Space Complexity = O(1)
```

---

# Analysis for Very Large Input Sizes

For very large arrays:

Example:

```
n = 100000
```

the number of comparisons becomes very large.

---

## Unoptimized Bubble Sort

The number of comparisons is approximately:

\[
\frac{n(n-1)}{2}
\]

For large `n`, this grows quadratically.

Example:

```
n = 100000
```

Comparisons ≈

```
5,000,000,000
```

This becomes extremely slow.

---

## Optimized Bubble Sort

For nearly sorted arrays:

- It detects that the array is almost sorted.
- It stops early.

Therefore, it performs significantly fewer comparisons.

However, for completely random or reverse sorted data, it still approaches:

```
O(n²)
```

# Conclusion

- Bubble Sort normally has a quadratic time complexity.
- The optimized version improves performance by stopping early when the array becomes sorted.
- The unoptimized version performs unnecessary comparisons.
- For nearly sorted input data, optimized Bubble Sort approaches **O(n)** behavior.
- For large input sizes, the optimized algorithm is significantly more efficient, while the unoptimized version becomes impractical due to excessive comparisons.
