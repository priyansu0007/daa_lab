# Q5. Find the Transition Point in a Sorted Binary Array

## Problem Statement

Given a sorted binary array containing only `0`s and `1`s, find the index of the **first occurrence of `1`**.

If the array contains only `0`s, return `-1`.

### Example

**Input:**
```text
arr = {0, 0, 0, 0, 1, 1, 1}
```

**Output:**
```text
Transition point found at index: 4
```

---

# C Program

```c
#include <stdio.h>

// Function to find the index of the first '1'
int findTransitionPoint(int arr[], int n) {
    int low = 0;
    int high = n - 1;
    int result = -1; // Default if no '1' is found

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (arr[mid] == 1) {
            result = mid;      // Record the position
            high = mid - 1;    // Search on the left for an earlier '1'
        } else {
            low = mid + 1;     // Search on the right
        }
    }

    return result;
}

int main() {
    int arr[] = {0, 0, 0, 0, 1, 1, 1};
    int n = sizeof(arr) / sizeof(arr[0]);

    int point = findTransitionPoint(arr, n);

    if (point != -1)
        printf("Transition point found at index: %d\n", point);
    else
        printf("No transition point (array contains only 0s).\n");

    return 0;
}
```

---

# Approach

Since the array is **sorted**, all `0`s appear before all `1`s.

Instead of checking every element one by one, we can use **Binary Search** to efficiently locate the first `1`.

### Steps

1. Initialize:
   - `low = 0`
   - `high = n - 1`
   - `result = -1`

2. Repeat while `low <= high`:
   - Find the middle index:
     ```c
     mid = low + (high - low) / 2;
     ```
   - If `arr[mid] == 1`:
     - Store `mid` as a possible answer.
     - Continue searching the **left half** because there may be an earlier `1`.
   - Otherwise (`arr[mid] == 0`):
     - Search the **right half** since the first `1` must be after `mid`.

3. Return `result`.

If no `1` is found, `result` remains `-1`.

| Iteration | low | high | mid | arr[mid] | Action | result |
|-----------|-----|------|-----|----------|--------|--------|
| 1 | 0 | 6 | 3 | 0 | Search right | -1 |
| 2 | 4 | 6 | 5 | 1 | Store 5, search left | 5 |
| 3 | 4 | 4 | 4 | 1 | Store 4, search left | 4 |

Loop ends because `low > high`.

**Final Answer = 4**

---

# Algorithm

1. Set `low = 0`, `high = n-1`, and `result = -1`.
2. While `low <= high`:
   - Compute `mid`.
   - If `arr[mid] == 1`:
     - Save `mid` in `result`.
     - Move `high = mid - 1`.
   - Else:
     - Move `low = mid + 1`.
3. Return `result`.

---

# Complexity Analysis

### Time Complexity

- Each iteration halves the search space.
- Therefore,

```text
Time Complexity = O(log n)
```

---

### Space Complexity

Only a few extra variables (`low`, `high`, `mid`, and `result`) are used.

```text
Space Complexity = O(1)
```

---

# Why Binary Search Works

The array is sorted in this form:

```text
0 0 0 0 1 1 1
```

- If the middle element is `0`, the transition must be to the **right**.
- If the middle element is `1`, the transition could be at the current index or **further left**, so we continue searching the left half.

This eliminates half of the remaining elements in every iteration, making the algorithm much faster than a linear search.
