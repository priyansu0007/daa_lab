# Canonical Huffman Coding

## 1. Problem Statement
Given a set of symbols and their corresponding frequencies, construct a prefix-free binary code of minimum expected length (standard Huffman coding) and output the **Canonical Huffman codebook**. In a canonical codebook, the assignment of 0s and 1s is standardized by ordering the codes lexicographically by their bit-length and then by the symbol itself. This standardization allows the entire codebook to be reconstructed using only the symbols and their code lengths, avoiding the need to transmit the full binary tree structure.

## 2. Approach
The problem is solved in two main phases: determining the optimal code lengths, and mathematically generating the standardized codes.

*   **Optimal Length Determination:** We build a standard Huffman tree. By repeatedly merging the two symbols (or combined nodes) with the lowest frequencies using a Min-Priority Queue, we create a tree that guarantees minimum expected code length. We then traverse this tree to extract the depth (bit-length) of each leaf node.
*   **Canonical Generation:** We discard the tree's arbitrary left/right branch assignments and rely purely on the extracted lengths. We sort the symbols primarily by length (shortest to longest) and secondarily by alphabetical order. The first symbol receives a code of all 0s. Every subsequent symbol's integer code is generated by taking the previous symbol's code, adding 1, and bit-shifting it to the left by the difference in their lengths.

## 3. Algorithm
1.  **Initialize Nodes:** Create a leaf node for every input symbol containing its frequency.
2.  **Build Tree:** While more than one node remains, extract the two nodes with the smallest frequencies. Create a new parent node with a frequency equal to their sum, attach the two nodes as children, and insert the parent node back into the active pool.
3.  **Extract Lengths:** Perform a Depth-First Search (DFS) from the root. When a leaf node is reached, record its symbol and its depth in the tree (which equals its code length).
4.  **Sort Lexicographically:** Sort the recorded `(symbol, length)` pairs ascendingly by length. If two symbols have the same length, sort them alphabetically by the symbol character.
5.  **Generate Canonical Codes:** 
    *   Assign the first symbol in the sorted list an integer code of `0`.
    *   For each subsequent symbol at index `i`, apply the formula: 
        `code[i] = (code[i - 1] + 1) << (length[i] - length[i - 1])`
6.  **Format Output:** Convert the generated integer codes into binary strings padded to their respective lengths.

## 4. Pseudocode
```text
function generate_canonical_huffman(symbols, frequencies):
    // Step 1 & 2: Build Standard Huffman Tree
    priority_queue = new MinHeap()
    for each (sym, freq) in (symbols, frequencies):
        priority_queue.push(Node(sym, freq))
        
    while priority_queue.size() > 1:
        left = priority_queue.pop()
        right = priority_queue.pop()
        parent = Node(symbol=NULL, freq=left.freq + right.freq, left, right)
        priority_queue.push(parent)
        
    root = priority_queue.pop()
    
    // Step 3: Extract lengths via DFS
    code_lengths = []
    function dfs(node, depth):
        if node is leaf:
            code_lengths.append( (node.symbol, depth) )
        else:
            dfs(node.left, depth + 1)
            dfs(node.right, depth + 1)
            
    dfs(root, 0)
    
    // Step 4: Sort by length, then symbol
    sort(code_lengths, key=lambda x: (x.depth, x.symbol))
    
    // Step 5: Assign Canonical Codes
    canonical_codes = []
    first_item = code_lengths[0]
    canonical_codes.append( (first_item.symbol, first_item.depth, 0) )
    
    for i from 1 to code_lengths.length - 1:
        prev_code = canonical_codes[i - 1].code
        prev_len = canonical_codes[i - 1].depth
        curr_sym = code_lengths[i].symbol
        curr_len = code_lengths[i].depth
        
        // Canonical shift formula
        new_code = (prev_code + 1) << (curr_len - prev_len)
        canonical_codes.append( (curr_sym, curr_len, new_code) )
        
    return canonical_codes
```

## 5. Complexity Analysis
*   **Time Complexity:** 
    *   Building the initial Huffman tree using a Min-Heap takes $O(N \log N)$ for $N$ symbols.
    *   The DFS traversal visits exactly $2N - 1$ nodes, taking $O(N)$ time.
    *   Sorting the extracted lengths takes $O(N \log N)$.
    *   The final sequential code generation evaluates each symbol exactly once in $O(N)$ time.
    *   **Overall Time Complexity:** $O(N \log N)$, dominated strictly by the sorting and priority queue operations.
*   **Space Complexity:** 
    *   The binary tree requires $2N - 1$ node allocations.
    *   The recursive DFS call stack reaches a maximum depth of $N$ in the worst case (highly skewed trees).
    *   Storing the codebook array takes $O(N)$ auxiliary space.
    *   **Overall Space Complexity:** $O(N)$, scaling strictly linearly with the number of unique input symbols.
